## 2. 测试用例

### 2.1 docs/todo 要点覆盖

| todo 项 | 测试方法 | 通过判据 |
| --- | --- | --- |
| `num_workers=4` 多进程分片正确性 | 阶段 4/5/6 均 `TRAIN_NUM_WORKERS=4`（真实 Linux 多进程 DataLoader + IterableDatasetShard） | 训练不崩、无限流持续推进、batch 内字符串字段正常 |
| effective_batch 验证 | 日志应含 `effective_batch=batch×world×accum`；单卡冒烟 batch=2×1×1=2 | 与公式一致；多卡场景（`TRAIN_NUM_PROCESSES=N`）复核 `2×N` |
| 训练冒烟 | 阶段 4：`--iters 30 --batch_size 2 --num_workers 4` | 30 步完成，loss 有限下降/震荡，GPU 显存不溢出 |
| resume 恢复 | 阶段 5：跑 30 步 → `--resume latest` 续到 45 | `global_step` 30→45，optimizer.pt 存在，loss 连续性 ratio∈(0.1,10) |
| resume × 冻结阶段交错 | 阶段 6：`freeze_steps=20`，10 步 ckpt 内 resume，续到 35 | resume 后 step<20 `lr_vlm=0`，step≥20 `lr_vlm>0`（解冻生效） |
| 图像预处理对齐 | 阶段 1 校验 `preprocessor_config.json` mean/std | 等于 ImageNet 统计（与训练侧一致） |
| 视频解码瓶颈量化 | 阶段 4 记录 `s/it`；对比 `TRAIN_NUM_WORKERS=1 vs 4` 的 `USED_CPU` | 记录实测数据，判断是否需优化（todo.md 方案 A/B 留档） |

### 2.2 日志格式

`train.py` 日志格式（get_logger）：`%(asctime)s | %(levelname)s | %(name)s | %(message)s`，datefmt=`%H:%M:%S`。
主进程写 stdout + `output_dir/train.log`（append）。

示例（阶段 4 检查正则）：
```
14:32:05 | INFO | train | [15/30] loss=1.2345 lr_core=0.00e+00 lr_vlm=0.00e+00 (1.02s/it) USED_CPU=1.23e+00 GB USED_GPU=5.67e+00 GB
```
检查项：行首时间戳、step 计数、`loss/lr_core/lr_vlm`、`effective_batch`、`USED_CPU/USED_GPU`。

### 2.3 resume 是否正常工作

- 阶段 5 覆盖：完整 checkpoint（`state.json` + `optimizer.pt` + per-rank `rng_state_rank{N}.pt` + 权重 + processor）；
  `--resume latest` 自动取最新 `ckpt-*`。
- 阶段 6 覆盖：冻结阶段内 resume，验证 `requires_grad` 冻结组状态在 resume 后正确恢复（阶段一冻结、阶段二解冻）。
- 判据见 2.1 表格。

### 2.4 保存的模型文件大小确认

- 阶段 4 记录 `ckpt-*/model.safetensors` 大小，与预训练 `model.safetensors`（≈3.52 GB）比较。
- 预期：阶段一仅 soft prompt + action 头训练，主权重基本不变 → ratio ∈ [0.8, 1.2]。
- 同时记录 `du -sh ckpt-*` 全目录大小（含 optimizer.pt、RNG 文件、processor、tokenizer）。

### 2.5 数据转换与 handler 是否符合预期

`scripts/check_data.py` 端到端覆盖：

| 检查项 | 预期 |
| --- | --- |
| 主表 `observation.state`/`action` | 形状 [N,20]、float32、行数一致 |
| `meta/stats.json` | state/action 20 维统计（min/max/mean/std/count/q01..q99），count=总行数 |
| `meta/info.json` | features state/action shape=[20] |
| `meta/episodes` | `stats/` 前缀列已剔除 |
| 视频 | 相机目录存在、symlink 目标存在（symlink 指回 src） |
| handler 样本 | domain_id=6、image_input[3,3,224,224]、proprio[20]、action[30,20]、指令非空、image_mask[3] |
| gripper 取值 | 反转后 ∈[0,1]（1-g 语义） |

此外阶段 3 跑 pytest（handler/dataset_reader/make_goai_20d），用 `XVLA_DATA_ROOT` 指到服务器数据。
注意 `test_handler.py` 的 `test_20d_matches_reference_conversion` 需要 16 维源数据（`ROOT_16`），
服务器缺 16d 源时该阶段自动 SKIP（check_data.py 仍覆盖 16→20 等价性主表维度检查）。

## 3. 执行步骤（服务器）

```bash
# 0. 同步代码到服务器（在本地）
rsync -avz --exclude 'runnings' --exclude '.git' \
  /Users/isuntaiyang/Documents/competition/X-VLA/ \
  root@117.50.215.108:/data/xvla_workspace/

# 1. 环境安装
ssh policy-server "cd /data/xvla_workspace && bash scripts/install_env.sh"   # 首次，约 10+ 分钟

# 2. 模型下载
ssh policy-server "cd /data/xvla_workspace && bash scripts/download_model.sh"

# 3. 数据准备（16d -> 6d）+ 数据/handler 验证
ssh policy-server "cd /data/xvla_workspace && bash scripts/prepare_data.sh"
ssh policy-server "cd /data/xvla_workspace && conda run -n xvla python scripts/check_data.py"

# 4. 全流程测试（阶段 0-6；或 --only N 单跑某阶段）
ssh policy-server "cd /data/xvla_workspace && bash scripts/run_server_tests.sh"
ssh policy-server "cd /data/xvla_workspace && tail -60 runnings/server_tests/summary.log"
```

长时训练（非冒烟）必须走 screen：
```bash
ssh policy-server "screen -dmS xvla_train bash -c 'cd /data/xvla_workspace && bash scripts/train.sh 2>&1 | tee /data/outputs/xvla_train.log'"
```
